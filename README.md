# layercfg — 分层部署配置编译工具

仅使用 Go 标准库实现的本地配置编译工具：合并公共参数文件与环境覆盖文件，
展开键间引用，输出可直接消费的 JSON 配置，以及供人工审查的来源报告。
工具不读取任何系统环境变量，所有输入均来自命令行指定的文件。

## 用法

```
go run ./cmd/layercfg compile <common.params> <env.params> <sensitive.json>
go run ./cmd/layercfg explain <common.params> <env.params> <sensitive.json>
```

- `common.params`：公共参数文件
- `env.params`：环境覆盖文件，同名键覆盖公共文件
- `sensitive.json`：敏感键名单，JSON 字符串数组，如 `["PASSWORD", "API_KEY"]`

## 参数文件语法

- 每行一条 `KEY = value`，`=` 两侧空白可选。
- 键名以英文字母或下划线起始，只含字母、数字、下划线。
- 空行与以 `#` 开头的整行注释被忽略（行内 `#` 不是注释）。
- 同一文件内重复定义同一键会报错，并定位到文件与行号。
- 值的三种写法：
  - 不带引号：去掉两端空白，参与 `${NAME}` 引用展开。
  - 单引号：内容按原文保留，不展开引用，不产生依赖。
  - 双引号：支持 `\\`、`\"`、`\n` 转义，参与 `${NAME}` 引用展开；
    其他转义或引号不闭合都会报出文件与行号。

## 引用展开

- 合并后（环境文件已覆盖公共文件）再展开 `${NAME}` 引用。
- 允许前向引用与间接引用（`A` 引用 `B`，`B` 再引用 `C`）。
- 引用未定义的键或出现循环依赖时报错，不输出任何部分配置。

## 敏感值处理

- 敏感键名单中的键，以及（沿依赖链）直接或间接引用了敏感键的键，
  都会被标记为敏感。
- `compile` 输出保留真实值，供部署直接消费。
- `explain` 报告与错误信息中敏感值一律以 `REDACTED` 代替，不会泄露。

## 两类输出

- `compile`：JSON 对象，键名稳定排序，值为展开后的真实配置，
  用于部署管线直接消费。
- `explain`：JSON 审查报告，按键名稳定排序，每个键包含：
  脱敏后的值、是否敏感、值的写法（bare / single-quoted / double-quoted）、
  来源文件与行号、依赖列表，以及被环境文件覆盖时的原定义位置。
  用于代码评审与部署前审计。

## 测试

```
go test ./...
```

覆盖跨文件覆盖、前向/间接引用、循环引用检测、缺失引用、
单引号原文保留、双引号转义、同文件重复键、解析错误定位，
以及敏感标记沿引用链的间接传播与报告脱敏。
